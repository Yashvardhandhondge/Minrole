- **Conversion rules** (SQL Server -> Postgres), follow exactly:
  - `IDENTITY(1,1)` -> `GENERATED BY DEFAULT AS IDENTITY`
  - `BIT` -> `BOOLEAN`
  - `DATETIME2` / `SYSUTCDATETIME()` -> `TIMESTAMPTZ` / `CURRENT_TIMESTAMP`
  - computed `Code` columns -> `GENERATED ALWAYS AS (...) STORED`
  - `LIKE` bracket patterns -> regex CHECKs
  - `DATEDIFF` / `DATEADD` -> Postgres date / interval expressions
  - no `GO` / `USE`; everything qualified as `dev."Name"`
  - the dependency-pair unique index -> COALESCE-based expression index named `"UX_Deps_Pair"`
  - Convert syntax only. Keep every table, column, PK, FK, unique key, CHECK and view.
    There is **no email table** (removed in v7).
- **Stack:** .NET 8 (`net8.0` in EVERY project — the demo machine "Accops" only has .NET 8).
  EF Core 8 + `Npgsql.EntityFrameworkCore.PostgreSQL` 8.*, **Database-First**.
  **Never** call `EnsureCreated()`, `dotnet ef migrations ...` or `dotnet ef database update` on this DB.
- **Team rules:**

  - **Never edit** files in `Models/Generated` or `Context/Generated`. Custom code goes elsewhere

  - Menus and logic go in `src/SecureShift.Console` (`Menus/`, `Services/`), written so they could

## 4. Rules for ALL later phases

- **Fresh reads:** every screen reads fresh from the DB — a new DbContext per action
  (`IDbContextFactory<SecureShiftDbContext>`) and `AsNoTracking()` for reads. Changes made in
  SQLTools must show the next time a menu opens. Never cache entities between menu actions.
- **Every write runs in a transaction** (`await using var tx = await db.Database.BeginTransactionAsync();` ... `CommitAsync`).
- **Audit:** important actions write `dev."AuditLogs"` (login, logout, user add/edit/reset,
  plan submit/approve/reject, etc.) in the same transaction as the change.
- **Role checks on every menu**; a user only sees their own role's menu.
- **Login:**
  - accepts ASP.NET Core Identity V3 hashes AND legacy uppercase SHA-256 hex; upgrades a legacy
    hash to V3 on successful login
  - blocks Inactive users
  - forces a password change when `MustChangePassword` is true
  - masks the password with `*`
- **Formulas, validations and status rules must match the prototype JS exactly.** Add tests that
  compare against seeded or prototype values.
- **Plain System.Console:** numbered menus, simple aligned tables, clear error messages,
  never crash on bad input.
- **Governance analysis** takes JSON file paths typed by the user (`File.ReadAllTextAsync` +
  `System.Text.Json`). Put sample JSON files in `samples/governance/`, in the format the prototype expects.
- No email, no DTOs, never edit Generated folders, never run EF migrations / EnsureCreated.
- Never commit a real password or connection string. Real values come from the env var
  `ConnectionStrings__SecureShiftDb` or the gitignored `src/SecureShift.Console/appsettings.Local.json`.
- Small commits with clear messages. If CI fails: `gh run view --log-failed`, fix, push, repeat
  until GREEN. Never say "should work" — prove it with a green run.

## 5. Database workflow

- Scripts in `database/postgres/`:
  - `01_create_secureshift_in_dev.sql` — one transaction, no CREATE SCHEMA, no DROP; fails on a name conflict.
  - `02_seed_data_postgresql_dev.sql` — 569 rows, same IDs; refuses unless all 28 tables are empty;
    resets identity sequences with `setval` at the end. Password hashes are Identity V3
    (generated by `tools/hash_passwords.js`).
  - `03_verify_dev.sql` — read-only: 28 tables, 4 views, 46 FKs, rows per table, 569 rows total.
  - `04_migration_history.sql` — creates `dev."__SchemaMigrations"` and records version 1 = baseline.
  - `migrations/V002__short_name.sql`, `V003__...` — future schema changes, one change per file,
    no BEGIN/COMMIT inside (the console wraps each file in its own transaction).
- Console DB commands: `db status`, `db setup`, `db seed`, `db migrate`, `db baseline`, `smoke`
  (see docs/backend/RUNNING.md). The faculty DB was set up by hand -> use `db baseline` there, never setup/seed.
- **Schema change recipe:** new `migrations/V00x__name.sql` -> `db migrate` -> run the
  **scaffold** workflow (`gh workflow run scaffold.yml --ref <branch>`) -> download the artifact ->
  replace `Models/Generated` + `Context/Generated` -> commit.
- Scaffold command (used by `.github/workflows/scaffold.yml`, do not change the options):
  ```
  dotnet ef dbcontext scaffold "<conn>" Npgsql.EntityFrameworkCore.PostgreSQL --project src/SecureShift.Data --startup-project src/SecureShift.Console --schema dev --context SecureShiftDbContext --context-dir Context/Generated --output-dir Models/Generated --namespace SecureShift.Data.Models.Generated --context-namespace SecureShift.Data.Context.Generated --no-onconfiguring
  ```
  Expected: 32 entity classes (28 tables + 4 keyless views) + `SecureShiftDbContext.cs`.
  Warnings about `"UX_Deps_Pair"` (expression index cannot be scaffolded) and collations are expected.

## 6. Technical notes (gotchas)

- Console project: AssemblyName `SecureShift.Console`, but **RootNamespace `SecureShift.ConsoleApp`**,
  so `Console.WriteLine` still means `System.Console` (a namespace called `SecureShift.Console` would hide it).
- The entity `Application` has the same simple name as the namespace `SecureShift.Application`.
  Put `using SecureShift.Data.Models.Generated;` **inside** the file-scoped namespace, or use an alias,
  when a file in a `SecureShift.*` namespace needs the `Application` entity.
- `timestamptz` columns map to `DateTime` with `Kind = Utc`. Always write `DateTime.UtcNow`
  (Npgsql throws for Local/Unspecified kinds). `date` columns map to `DateOnly`.
- Generated columns (`Code`, `PeriodDays`, `RiskLevel`, `Category`) are read-only; never set them.
- Postgres names are case-sensitive: always quote, e.g. `SELECT * FROM dev."Users"`.
- Npgsql EF maps the views as keyless entities (`HasNoKey()`); query them with `AsNoTracking()`.
- `OutputType` must be `Exe` for the console (otherwise CS8805 with top-level statements).
