# SecureShift - the complete video walkthrough

Every step, every role, every menu option, with the typed inputs visible (passwords appear as `*****`, as the
app masks them). Recorded with [VHS](https://github.com/charmbracelet/vhs) in **Windows PowerShell**, against the real
app (the offline package) and a real PostgreSQL 16 database, starting from zero.

The videos are **not** in the repository. They are attached to the GitHub pre-release **demo-full**:
https://github.com/Yashvardhandhondge/Minrole/releases/tag/demo-full

## How it is made

| File | What it is |
|---|---|
| [clips.js](clips.js) | the walkthrough as data: every clip, every key, the expected text, the menu-option checklist; writes the tapes and the docs |
| [tapes/](tapes/) | one VHS tape per clip (`NN-role-task.tape`), generated by `clips.js` - do not edit by hand |
| [sql/](sql/) | the SQL files a "teammate" runs with `psql -f` in the live-change clips |
| [transcripts/](transcripts/) | what each clip shows, as text (from the dry run) |
| [layout.json](layout.json), [timeline.json](timeline.json) | screen heights (for scrolling long screens) and the timing used for the coverage start times |
| [../../../scripts/windows/record-full-demo.ps1](../../../scripts/windows/record-full-demo.ps1) | records everything with one command |

The clips run **in order on one database**, so the data flows from one clip to the next: the company added in
clip 06 is analysed in clip 08, the enterprise registered in clip 14 is classified in clip 15, its applications are
assessed in clips 19-20, simulated in 21, planned in 22-23 and approved / rejected by the Executive in 24.

Screens taller than the terminal (about 131 x 35 characters at font size 25) are shown completely: the video scrolls
up to the first line of the screen and back down. Pauses: 2 s after each screen, 3 s on important results (scores,
temporary passwords, plan phases, approvals).

## Re-record with one command

On Windows, with VHS, ttyd, ffmpeg and the PostgreSQL 16 zip in `C:\SecureShiftTools` (see
[../../backend/TCS_LAPTOP_SETUP.md](../../backend/TCS_LAPTOP_SETUP.md)), Microsoft Edge, Node.js and the .NET 8 SDK:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\record-full-demo.ps1
```

It builds the offline package, moves your own `C:\SecureShiftTools` database aside, runs a dry run of every clip
(checks every expected text), writes the tapes, records all clips, adds the title cards, joins the FULL video and the
per-role videos, writes the chapters / subtitles / coverage times, checks a frame every 3 s with the Windows OCR, and
puts your database back. The videos are in `C:\Demo\output`. Delete `C:\Demo` afterwards with `-Steps cleanup`.

Change something in one clip: run without the `restore` step (the demo database stays), edit [clips.js](clips.js),
then dry-run and re-record from that clip - the database is first restored to the snapshot taken after the clip
before it - and restore your own database at the end:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\record-full-demo.ps1 -Steps dryrun,tapes,record,assemble,check -From 12
powershell -ExecutionPolicy Bypass -File scripts\windows\record-full-demo.ps1 -Steps restore
```
